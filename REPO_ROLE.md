# Repository Role — Public Project Guide

**ToF Showcase** is the main public entry point for the ToF Systems project family. It is an orientation and architecture repository, **not** a runnable product or a copy of the private runtime.

## Choose what to read

1. Start with [the overview](README.md) to identify the public project that solves your problem.
2. Open the relevant product repository to find its quickstart, actual capabilities, and limits:
   - [Container Pulse](https://github.com/IMaugrenI/tof_container_pulse) — observe local infrastructure.
   - [Local Knowledge](https://github.com/IMaugrenI/tof_local_knowledge) — find evidence in documents.
   - [Local Builder](https://github.com/IMaugrenI/tof_local_builder) — use bounded local AI development.
   - [Local Case Organizer](https://github.com/IMaugrenI/local_case_organizer) — organize local document sets.
3. Read [the architecture reference](https://github.com/IMaugrenI/tof-v7-public-frame) if you want to understand historical design boundaries.
4. Explore the separate recovery, planning, and module-ideas repositories for supporting methods.

## Historical terminology

Older documents sometimes distinguish **ToF** (technical structure) from **V’eth** (identity and expression). These names describe a specific separation in the earlier architecture; they are not prerequisites for using ToF Systems public tools.

## Public and private boundaries

Cross-repository links are for navigation. They do not imply one combined runtime, shared legal terms, identical licenses, or identical maturity and disclosure levels.

Public design explanations do not establish the current state of private infrastructure. Each runnable project is responsible for documenting its own implementation.
